# B2B MarTech Intel

## Overview

B2B MarTech Intel is an AI-powered platform designed for B2B Marketing and Sales Technology professionals. It aggregates news and analyzes market trends. The project provides market intelligence through news aggregation, Morning Brief emails, trend visualization, company analysis, competitor research, and Google Drive document imports.

## System Architecture

The application utilizes a client-server architecture.

**Frontend:**
Developed with React, Vite, TailwindCSS, and shadcn/ui for a responsive user interface. It incorporates `wouter` for routing and PWA capabilities. Route-based code splitting via `React.lazy()` keeps the initial JS bundle small (only NewsFeed is statically imported; all other pages are lazy-loaded). UI/UX focuses on clean design, dynamic filtering, interactive data visualization, and adherence to specific brand guidelines (Demandbase colors: Midnight, Sky, Sunset).

**Backend:**
Built with Express.js, providing a REST API and Server-Sent Events (SSE) for real-time communication. It handles data aggregation, AI integrations, and database interactions. The production server is bundled to CommonJS by esbuild (`script/build.ts`) with dependencies left external EXCEPT an explicit allowlist — ESM-only packages (e.g., `p-retry`) MUST be added to that allowlist or production fails at runtime with a require/interop error while dev and tests pass.

**Database:**
PostgreSQL is the primary data store, managed with Drizzle ORM. It uses `tsvector` for full-text search and includes an auto-seeded `news_categories` table. The `articles` table has performance indexes on `published_at DESC`, `category`, `source_id`, `dismissed`, and a composite index on `(dismissed, category, published_at DESC)` for the main query pattern. Indexes were created via direct SQL (not Drizzle schema) to avoid interactive `db:push`. IMPORTANT: any DB object created at runtime MUST also be mirrored in `shared/schema.ts` (see the modeled `search_vector` tsvector column and the `source_fetch_failures` / `source_blocked_items` tables) — otherwise `drizzle-kit push` proposes dropping it. This applies to **indexes**, not just tables: `briefs_real_daily_uniq` (a partial unique index created in `server/morning-brief/ensure-table.ts`) went unmodeled for weeks and only surfaced during a 2026-08-12 review, one step before a push that would have offered to drop the only guard against duplicate scheduled briefs. It is now modeled as `uniqueIndex(...).on(...).where(sql\`manual = false\`)`. Newer additions (`articles.guid`, `articles.tags` + GIN index, `feed_tags`) live in the Drizzle schema and were applied via `db:push` against the Railway DB using its public proxy URL.

**AI & Machine Learning:**
Integrates Gemini 2.5 Flash (via Replit AI Integrations) for brand-compliant content generation. OpenAI is used for trend analysis, topic classification, and public company analysis, facilitating executive briefings, content summarization, and strategic assessments. Claude Sonnet 4.6 is used for document upload AI structuring, AI feedback, document image and video analysis.

**Core Features & Technical Implementations:**
- **Automatic news retention (2026-10-24):** `server/article-retention.ts` keeps 30 days of news using the earlier of publication and ingestion time (undated stories use ingestion time). A startup catch-up and hourly scheduler delete expired news in 500-row transactions, clear stored news bodies, and adjust tag counts. Briefs and delivery history, knowledge-base records, saved research, and uploaded documents are preserved. RSS and NewsAPI use the same atomic age/dedup guard: SHA-256 URL/source-GUID receipts live 90 days since last seen, and stale dated stories are rejected even after a receipt expires. Receipt creation/deletion and ingestion share a transaction advisory lock; a separate session lock prevents overlapping cleanup. Normal vacuum makes freed space reusable; initial operator-run VACUUM FULL returns old archive space to the volume. Additive migration: `migrations/20261024_article_retention.sql` (all objects mirrored in `shared/schema.ts`). Operator CLI defaults to preview: `railway run --service Postgres --environment production npx tsx script/article-retention.ts --dry-run`; use `--apply` for cleanup. Database integration tests run with `TEST_DATABASE_URL` set to an isolated PostgreSQL instance; they create and drop only their own test schema. Historical news search is limited to retained articles; saved brief/report snapshots remain available.
- **News Aggregation:** Gathers articles from RSS feeds, Google News, and NewsAPI, with dynamic filtering (including custom date range picker) and a recommendation system. Feeds are automatically fetched on server startup and refreshed every 30 minutes in the background. The News Feed page loads instantly from cached database articles; a manual "Refresh" button and "last updated" timestamp let users trigger on-demand fetches without blocking page load.
- **Feed Tags:** Publisher RSS categories are normalized (`server/tags.ts`) and saved per article. Existing tags, cached annotations, moderation statuses, approved tag filters, and blocked-tag ingestion rules are preserved. AI tagging is disabled (2026-10-24): NewsAPI ingestion makes no tagging calls, no boot/daily catch-up sweep is scheduled, opening the review queue generates no AI summaries or suggestions, and the historical backfill command refuses to run. Manual moderation and publisher-tag counts remain active. Morning Brief composition is unchanged and does not require article tags.
- **Morning Brief (Push Email):** Weekday-morning email digest (default 7:00 America/Chicago, config via `BRIEF_HOUR`/`BRIEF_TZ`/`BRIEF_RECIPIENTS`; malformed hour falls back to 7 with a logged warning) composed by Claude Sonnet from the last 24h of articles (72h cap covers weekends), trend snapshot deltas, and competitor mentions. Structured `BriefPayload` (shared zod schema; model-generated links are validated http(s)-only and deep links app-relative to block scheme abuse) renders to branded HTML email via Resend and to the in-app `/morning-brief` archive page, which includes a collapsible "How it works" explainer (auto-expands when the archive is empty). In-process 5-min scheduler (re-entrancy-guarded tick) with a `briefs` table ledger (partial unique index; `manual` test sends never block the daily send), 3 compose attempts — pre-send render failures re-enter the compose ladder rather than looping — then a fallback headlines email — a weekday morning never passes silently. Composer output cap is 8192 tokens (4096 truncated real payloads). Both composition and schema repair have a four-minute timeout at the application and SDK layers; other AI calls keep their two-minute default. This prevents valid background briefs from being aborted at the interactive deadline (the cause of the September 15–17 fallback emails). First production send 2026-07-08. Module: `server/morning-brief/`. Single-replica assumption: the tick's in-flight guard is per-process — do not scale this service above 1 replica without moving the send claim into SQL.
- **Briefings Hub (`/briefings`):** Two tabs — Morning Brief (email digest archive, above) and Deep Reports (AI trend reports, from the Trends system). The former Daily Briefing (on-demand executive summaries, Compare, Time Machine) was removed 2026-07-13 — Morning Brief supersedes it; the `briefings` table and `/api/briefings/*` endpoints no longer exist.
- **Morning Brief recipients (2026-10-26):** The Email recipients panel under Briefings → Morning Brief lets trusted workspace admins add/remove email recipients without granting app access. A durable `brief_recipient_settings` row imports `BRIEF_RECIPIENTS` once; subsequent changes use the database, including a deliberately empty list that pauses scheduled sends. Addresses are normalized, validated, deduplicated, and capped at 50; row locks serialize edits. Scheduled/manual sends read the saved list. Delivery snapshots retain their original recipients and sender on retries. `BRIEF_FROM_EMAIL` configures a verified Resend sender; the UI warns when the legacy testing sender is still in use. Apply `migrations/20261026_brief_recipients.sql` before deployment. Adding a recipient does not send an immediate email.
- **Trends:** Features an AI-powered trend snapshot system with a dashboard displaying AI-identified B2B GTM trends (collapsible), emerging signals (collapsible), and company sentiment. Snapshot history dropdown shows "Date Range - Model Name" format. Competitive Intelligence tracks all companies from Sources Competitor Database. Supports historical snapshot selection, category filtering, custom date range filtering, and a Trend Watchlist for tracking specific trends across snapshots over time (with momentum/confidence history, notes, pause/resume, and fuzzy name matching).
- **DB POV (Knowledge Base):** An editable knowledge base with AI-extracted entries used by Morning Brief; structured product knowledge also informs Public Company Analysis. It includes a knowledge approval workflow, structured product knowledge with hierarchical product types (suites, products, sub-products at any nesting level, and features on any product level), manual product/sub-product creation, feature duplication across products, drag-and-drop nesting of products into suites or other products (with cycle prevention), and overlap detection.
- **Research:** Web crawler-based competitive intelligence system with two tabs: Company Intel (crawl Demandbase website) and Competitor Research (track/crawl competitor sites). Features BFS web crawler with same-domain filtering, depth/page limits, rate limiting, and SSRF protection. AI extraction pipeline uses Claude/GPT to extract structured knowledge entries from crawled pages. Entries can be reviewed (approve/reject), batch-managed, and pushed to the Knowledge Base with conflict detection. Database tables: `crawl_jobs`, `crawl_pages`, `crawl_entries`.
- **Sources Management (Knowledge Quality Detection):** Supports adding and managing RSS feeds, NewsAPI queries, and document uploads. It includes AI-powered conflict/quality detection for knowledge entries with actionable AI Assist suggestions (merge duplicates, delete redundant entries, update outdated content, clarify vague entries) that execute via `/api/knowledge/consolidate` and `/api/knowledge/ai-rewrite` endpoints.
- **Source Report (shipped 2026-08-12):** Sources → Report ranks all 105 feed sources by volume so dead weight is visible — `lastFetchedAt` only proves a fetch *ran*, so a feed returning an empty or stale window used to look identical to a healthy one. Columns: 30d and retained article counts, last-article date, retained dismissed count + rate, blocked-at-ingest count, and fetch-failure days. Computed on request by one aggregate query (`storage.getSourceReport` → `GET /api/sources/report`) joining `sources` against grouped subqueries over `articles`, `source_blocked_items`, and `source_fetch_failures`; deliberately NOT denormalized counters (that is the `feed_tags.article_count` inflation bug). Every count is `::int`-cast so node-pg returns numbers, not bigint strings. Filter chips All / Silent (0 in 30d) / Failing are **independent predicates, not mutually exclusive classes** — a source that is both silent and failing (the worst case) must appear under both, which is why the filter does not compare against `classifySource`. Rows pause via the existing PATCH and delete behind `ConfirmDestructive`, whose copy names the article count `deleteSource` will destroy along with the source. Display logic lives in pure functions in `shared/source-report.ts` (unit-tested — the client has no test harness). Excludes uploaded docs (`feed_url LIKE 'upload://%'`) and NewsAPI articles (`source_id IS NULL`, so they are structurally invisible to a `sources`-joined report). Component: `client/src/components/source-report-tab.tsx`.
- **Blocked-ingest instrumentation (shipped 2026-08-12):** `server/rss.ts` used to skip admin-blocked-tag articles with a bare `continue`, recording nothing. It now writes to `source_blocked_items` (`INSERT … ON CONFLICT (source_id, link) DO NOTHING`, so an item reappearing every 30-minute cycle counts once), wrapped in try/catch like `recordFetchFailure` — instrumentation must never break ingest, and it degrades cleanly if the table is missing. No backfill is possible, so counts start at zero and the UI renders `—` rather than `0` for a source not yet fetched since ship.
- **Topic Tracking & Company Tracker:** Manages topics and categories, including automated Google News RSS source creation for tracked companies.
- **Public Company Analysis:** AI-driven analysis of public companies, providing detailed reports with a Q&A section for follow-up questions grounded in the analysis data.
- **Voice Input:** Integrated `VoiceInputButton` for speech-to-text transcription using OpenAI's `gpt-4o-mini-transcribe`.

**Shared Components:**
A `MarkdownRenderer.tsx` component is used across the application for consistent markdown formatting.

**File Processing Pipeline:**
A unified, database-backed processing queue (`processing_jobs` table) handles file uploads up to 50MB for various types (PPTX, PDF, DOCX, TXT, images, videos). It supports asynchronous processing, progress tracking, and UI display of active and recent jobs. The pipeline includes text extraction, image/video frame extraction, and AI vision analysis using Claude Sonnet 4.6 for descriptions.

## Security and release controls (2026-09-12)

- **Private workspace:** Google sign-in accepts only verified emails in `ALLOWED_EMAILS`. Every approved account is a trusted workspace administrator; this is not a tenant-isolated SaaS. Server-side PostgreSQL sessions expire absolutely after 8 hours. Unsafe API methods require the configured same-origin header. Missing auth configuration denies business API access.
- **Uploads:** Completed chunk uploads use owner-bound one-use IDs; client filesystem paths are rejected. Uploads are capped at 50MB, chunks at 6MB, and pending manifests expire after 30 minutes. Office extraction caps actual expanded bytes; PDF parsing uses a separate process with a 30-second kill deadline, 128MB V8 heap and sampled Linux RSS guard.
- **Outbound content:** RSS, knowledge URLs and research crawling use the shared public-address/DNS-pinned fetcher with redirect revalidation, total deadline and response-byte limits.
- **Admission and AI:** Concurrent writes/background jobs and analytics ranges are bounded. AI calls reserve durable daily input-byte-plus-output-token units and call counts before provider work. These are conservative admission limits, not dollar estimates or actual usage. Provider timeouts, explicit completion checks and structured-result validation prevent incomplete content from being silently saved.
- **Recovery and delivery:** Interrupted jobs become explicit retryable failures after a 30-second handoff grace following first readiness; recovery retries database failures up to five times. This assumes the configured single replica and zero handoff overlap, not distributed worker fencing. Morning Brief persists a delivery snapshot and stable provider idempotency key; ambiguous deliveries older than 23 hours require review.
- **Logs and caches:** Request logs contain route templates/status/timing only. Protected images and API responses are excluded from service-worker caching; sign-out clears browser query state.
- **Release:** Set `RAILPACK_NODE_NPM_INSTALL=npm ci --include=dev` for deterministic installation in Railpack's install step. `railway.json` then runs typecheck, tests and bundle compilation; build performs no schema push. Do not run npm ci in the build step, where Vite's mounted cache prevents removal of node_modules. Apply reviewed additive SQL in `script/security-auth.sql`, `script/security-budget.sql`, and `script/migrations/2026-09-12-brief-delivery.sql` before deploying this release. `/healthz` checks required database schema with a short deadline. Keep one replica with no rolling overlap until jobs have cross-process leases.
- **Configuration:** Set APP_BASE_URL, AUTH_GOOGLE_CLIENT_ID, AUTH_GOOGLE_CLIENT_SECRET, ALLOWED_EMAILS and a randomly generated SESSION_SECRET in Railway; authorize APP_BASE_URL + `/api/auth/google/callback` in Google. Drive OAuth is separate. See `.env.example` for AI admission knobs.

Old page URLs redirect to Briefings. New Morning Briefs omit content ideas; rendering older payloads links to Trends. Saved chat sessions/messages, generated content, TL documents, and article digests remain in their existing tables; no schema migration or data deletion. Removed the unused article-digest AI generation after manual feed refresh. Shared knowledge, search indexing, and Drive imports remain.
